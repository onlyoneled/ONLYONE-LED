# LED 견적 예상 계산기 (Phase 2) 설계

## 배경

Phase 1(별도 세션)에서 269개 실제 위챗 견적서를 분석해 LED 전광판 원가 데이터를
카테고리별(LED모듈/수신카드/SMPS/프로세서/박스/케이블 3종/우드박스/운송비)로
정규화·집계한 `온리원LED_원가데이터_추출.xlsx`를 만들었다. 이 문서는 그 데이터를
써서 **화면 사이즈만 입력하면 예상 견적이 나오는 새 계산기**를 만드는 작업(Phase 2)을
설계한다.

기존 두 계산기는 **절대 수정하지 않는다** (사용자 명시 요구사항):
- [led-layout-calc.html](../../../led-layout-calc.html) — "다이캐스팅 배치 계산기". 화면 W×H와 모듈 피치를 넣으면
  캐비닛 구성(640×640/640×480 등 개수), 모듈 수량, 전력, 브레이커, 데이터라인 수를
  산출하는 순수 물리 계산기. 원가 없음.
- [led-cost-calculator.html](../../../led-cost-calculator.html) — 신커차이(深科材) 한 업체 샘플 견적을 하드코딩한
  원가 계산기. 실내 320×160mm 모듈 1종, 박스 2사이즈만 지원.

## 목표

새 페이지 `led-quote-estimator.html`에서 화면 사이즈(가로×세로 mm)와 LED 모듈
종류를 입력하면, Phase 1에서 뽑은 실제 관측 단가를 근거로 항목별 소계 + 총 예상
견적이 자동으로 나오게 한다.

## 데이터 흐름

```
온리원LED_원가데이터_추출.xlsx (Phase 1 산출물, 사용자가 검토/수정 가능)
  → convert_cost_data.py (신규, Python)
  → data/led-cost-data.js (신규, 정적 JS 객체 — 페이지가 <script>로 로드)
  → led-quote-estimator.html (신규)
      1) 배치 엔진(led-layout-engine.js 로직을 이 파일 안에 복사 — 원본 미수정)
         으로 화면 사이즈 → 캐비닛 구성/모듈 수량/데이터라인 수 계산
      2) led-cost-data.js의 대표단가를 곱해 항목별 소계 산출
      3) 결과 표시
```

xlsx를 나중에 검토·수정하면 `convert_cost_data.py`만 다시 돌려 `led-cost-data.js`를
갱신하면 된다 — 페이지 코드는 안 건드려도 된다.

## SMD vs GOB/COB 분리

Phase 1 데이터의 LED모듈 `type` 속성(SMD/GOB/COB)을 기준으로 변환 스크립트가
데이터를 두 그룹으로 나눠 `led-cost-data.js`에 담는다:
- `LED_MODULES_SMD` — 기본 탭. 관측이 충분한(권장: 관측횟수 ≥2) SMD 피치만 포함.
- `LED_MODULES_GOB_COB` — 별도 탭. "타사(COB 전문업체) 참고 데이터"로 명확히
  라벨링하고, 페이지 상단에 "다른 업체 데이터이므로 참고용" 안내문을 고정 표시한다.

두 그룹의 원가 계산 로직(배치 엔진, BOM 배율)은 동일하게 재사용하되, 탭을 전환하면
현재 선택된 모듈 그룹의 단가만 반영된다. 실제 COB 전용 매입 프로세스나 COB만의
BOM 배율 차이는 이번 범위 밖 — 향후 COB 업체 견적이 쌓이면 별도로 다듬는다.

## BOM 배율 규칙 (신규 — 배치 엔진 출력과 원가 데이터를 잇는 다리)

배치 엔진은 화면 크기로부터 다음을 계산해준다: `cabinets`(사이즈별 개수 목록),
`totalCabinets`, `totalModules`, `dataLines`. 원가 데이터는 "부품 1개당 단가"만
갖고 있으므로, 화면 하나에 부품이 몇 개 필요한지는 다음 규칙으로 정한다
(기존 led-cost-calculator.html이 쓰던 박스당 배율과 같은 성격의 가정 — 사용자가
검토 후 조정 가능하도록 화면에 "가정" 문구로 명시):

| 항목 | 수량 규칙 |
|---|---|
| LED 모듈 | `totalModules` × 모듈 단가 |
| 다이캐스팅/철함체 박스 | 캐비닛 사이즈별 개수 × 해당 사이즈 박스 단가 (사이즈 매칭 안 되면 가장 가까운 사이즈로 대체 + 경고) |
| 수신카드 | `totalCabinets` × 1개 × 선택한 모델 단가 (캐비닛당 1개 가정) |
| SMPS | `totalCabinets` × 1개 × 선택한 모델 단가 |
| 220V 케이블 | `totalCabinets` × 1개 |
| CAT6 케이블 | `totalCabinets` × 1개 |
| 16P 플랫케이블 | `totalCabinets` × 1개 |
| 프로세서 | 1대 × 선택한 모델 단가 (데이터라인 수가 많아 1대로 부족해 보이면 경고만 표시, 자동 대수 산정은 범위 밖) |
| 우드박스 | 화면 면적(㎡)에 가장 가까운 `area_bucket_sqm` 관측치의 대표단가 |
| 운송비 | 우드박스와 동일한 방식 |

수신카드/SMPS/프로세서는 브랜드+모델 드롭다운으로 사용자가 고르게 한다(기존
led-cost-calculator.html과 같은 패턴) — 목록은 `led-cost-data.js`에 들어있는
모든 관측된 모델을 관측횟수 내림차순으로 정렬해 보여준다.

## 데이터 신뢰도 경고

각 소계 항목 옆에 관측횟수를 작게 표시하고, 다음 경우 노란 경고 배지를 띄운다:
- 관측횟수 1~2건 (표본이 매우 적음)
- 화면 면적이 우드박스/운송비 관측 범위(최소~최대 area_bucket) 밖 — 가장 가까운
  버킷 값을 썼다는 것과 실제 값과 차이가 클 수 있다는 것을 명시
- 박스 사이즈가 정확히 매칭되지 않아 근사값을 썼을 때

억지로 정밀한 척하지 않고, 데이터가 약한 부분은 약하다고 보여주는 것을 원칙으로 한다
(Phase 1과 같은 원칙).
